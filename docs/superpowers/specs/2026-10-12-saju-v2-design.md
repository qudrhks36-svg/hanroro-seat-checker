# 사주 웹서비스 v2 설계

v1(`2026-10-08-saju-web-design.md`)을 확장한다. 이 문서가 `2026-10-12-saju-v2-brainstorm-notes.md`를 대체한다. 서버 없는 정적 사이트, 규칙 기반, 같은 입력은 항상 같은 결과라는 v1 제약은 그대로다.

## 배경과 목표

사용 후기: (1) MBTI와 사주의 공통점을 시각적으로 보고 싶다, (2) 풀이가 줄글이라 읽기 힘들다, (3) 기존 사주 앱과 비슷하고 지루하다.

v2는 세 가지를 한 번에 바꾼다.
1. **사주 → MBTI 4축 예측**: MBTI 입력 없이 E/I, S/N, T/F, J/P 비율과 근거, 조언을 보여준다. 실제 MBTI를 선택 입력하면 벤다이어그램으로 비교한다.
2. **줄글 → 카드형**: 풀이를 `요약 · 키워드 칩 · 불릿 · 세기 막대`로 바꾸고 기존 줄글은 "더 보기"로 접는다.
3. **재미 요소**: 사주 기반 캐릭터와 닉네임, 상황별 말풍선, 공유 카드 개편.

## 사용자 대면 문구 원칙

- v1 원칙 유지: 전문가 톤, "재미/오락용" 면책 문구 금지, 흉운·질병·사망 단정 금지, 의료·투자 판단 금지.
- MBTI 예측에는 방법을 밝히는 표기를 넣는다: **"사주 기운을 MBTI 축으로 번역한 경향"**. 정확도를 주장하지 않는다. 유형 라벨로 단정하지 않고 "~일 확률이 높아요" 형태를 쓴다.

## 1. MBTI 4축 예측 (`src/lib/mbti.ts`)

### 입력 특징

`Analysis`(v1)에서 계산한다. 시간 모름이면 시주가 빠진 6글자 기준으로 그대로 계산한다.
- `el(e)` = `elements[e] / 오행 합계` (木火土金水 각각의 비중, 합 = 1)
- `g(x)` = `groups[x] / 십성 그룹 합계` (비겁·식상·재성·관성·인성 비중, 합 = 1)
- `yang` = 일간이 양(甲丙戊庚壬)이면 +1, 음이면 −1

### 축별 점수

각 축은 첫 글자 쪽 합 A와 둘째 글자 쪽 합 B의 차 `d = A − B + bonus`로 계산한다.

| 축 | A (E / S / T / J 쪽) | B (I / N / F / P 쪽) |
|---|---|---|
| E/I | 0.5·(el화+el목) + 0.5·(g비겁+g식상) | 0.5·(el수+el금) + 0.5·(g인성+g관성) |
| S/N | 0.5·(el토+el금) + 0.5·g재성 | 0.5·(el목+el수) + 0.5·g식상 |
| T/F | 0.5·(el금+el수) + 0.5·g관성 | 0.5·(el화+el토) + 0.5·g인성 |
| J/P | 0.5·(g관성+g재성) + 0.5·(el토+el금) | 0.5·(g식상+g비겁) + 0.5·(el목+el화) |

`bonus` (모두 첫 글자 쪽이 +, 둘째 글자 쪽이 −):
- **일간 오행 보너스**: 일간 오행이 그 축의 A쪽 오행에 속하면 +0.15, B쪽 오행에 속하면 −0.15 (A쪽/B쪽 오행은 위 표의 `el` 항목과 같다. 속하지 않으면 0).
- **일간 음양 보너스**: E/I 축만, `+0.10 × yang`.

변환: `pctFirst = clamp(round(50 + 40 · d), 15, 85)`. 둘째 글자 쪽은 `100 − pctFirst`.

### 출력 (`MbtiPrediction`)

```ts
type AxisResult = {
  axis: 'EI' | 'SN' | 'TF' | 'JP'
  letters: [string, string]         // ['E','I'] 등
  pctFirst: number                  // 15~85
  lean: string                      // pctFirst >= 50 이면 첫 글자, 아니면 둘째 글자
  balanced: boolean                 // |pctFirst − 50| < 10 이면 "비슷해요"로 표시
  reasons: { label: string; points: number }[]   // lean 쪽을 가장 크게 민 요소 2개, points = 기여 × 40 (반올림)
}
type MbtiPrediction = { axes: AxisResult[4]; type: string }   // type = 각 축 lean 글자 4개
```

`reasons.label` 예: `화(火) 기운`, `관성`, `일간 오행(토)`, `일간 음양`.

### 분포 검증 (구현의 합격 조건)

1930~2029년 사이를 13일 간격, 정오 기준으로 돌린 표본에서 다음을 만족해야 한다. 어긋나면 `gain`(40) 또는 보너스 값을 조정하고 변경 이력에 기록한다.
- 축별 `pctFirst` 평균이 42~58
- 15 또는 85에 붙는 비율이 축별 10% 미만
- 40~60 구간(균형) 비율이 축별 50% 미만 (대부분 "비슷해요"면 재미가 없다)
- 16유형 중 12가지 이상이 표본에 등장

### 샘플 손계산 (테스트 기대값, gain 40 기준)

샘플: 庚午 己卯 己卯 己巳. 오행 木2 火2 土3 金1 水0 (합 8), 십성 비겁2 식상1 재성0 관성4 인성2 (합 9), 일간 己(土, 음).
`el목=.25 el화=.25 el토=.375 el금=.125 el수=0`, `g비겁=.2222 g식상=.1111 g재성=0 g관성=.4444 g인성=.2222`.

| 축 | A | B | A−B | 보너스 | d | pctFirst | 결과 |
|---|---|---|---|---|---|---|---|
| E/I | .4167 | .3958 | +.0208 | 음양 −.10 (土는 오행 보너스 없음) | −.0792 | 47 | I 53%, 균형 |
| S/N | .25 | .1806 | +.0694 | 일간 土 ∈ S쪽 +.15 | +.2194 | 59 | S 59%, 균형 |
| T/F | .2847 | .4236 | −.1389 | 일간 土 ∈ F쪽 −.15 | −.2889 | 38 | F 62% |
| J/P | .4722 | .4167 | +.0556 | 일간 土 ∈ J쪽 +.15 | +.2056 | 58 | J 58%, 균형 |

예측 유형 **ISFJ**. 이 값은 gain 40 기준이다. 분포 검증에서 `gain`이나 보너스를 바꾸면 이 표와 테스트 기대값을 같이 갱신한다. 샘플에서 4축 중 3축이 "균형"으로 나오므로, 분포 검증의 "균형 비율" 합격 조건이 `gain` 상향(예: 60)의 신호가 될 수 있다.

### 문구 (`src/data/mbti.json`)

축 4 × 우세 쪽 2 = 8경우마다 `advice`(이렇게 살면 좋다, 한 줄)와 `minor`(약한 쪽 비율이 어떻게 작용하는지 설명, 한 줄) = 16문장. 예: F 우세일 때 `minor`는 T 비율이 판단에서 어떻게 쓰이는지 설명.

## 2. 실제 MBTI와 비교 (`src/lib/compare.ts` + `VennCompare`)

- 입력 위치: 결과 화면의 MBTI 카드 안의 4축 선택 버튼(E/I, S/N, T/F, J/P 각각 하나). 저장하지 않는다.
- 계산: `matched` = 예측 lean 글자와 실제 글자가 같은 축. `onlySaju` = 다른 축의 예측 글자, `onlyMbti` = 다른 축의 실제 글자. `score = matched 개수 / 4`.
- 불일치 축 설명: 실제 글자 쪽 비율이 35% 이상이면 "사주에서도 {글자} 쪽이 {pct}%로 꽤 있는 편입니다", 미만이면 "사주 경향과 다른 축입니다".
- 시각화: SVG 두 원. 왼쪽 "사주가 말하는 나"(`onlySaju` 칩), 오른쪽 "내 MBTI"(`onlyMbti` 칩), 가운데(`matched` 칩)와 `N/4 일치`. 라이브러리는 쓰지 않는다.

## 3. 사주 캐릭터 (`src/lib/character.ts`, `src/data/character.json`)

`buildCharacter(pillars, analysis)` → `{ emoji, prop, propName, nickname, job, animal, tone, accent, bubbles }`.

| 요소 | 규칙 |
|---|---|
| 일간 → 동물, 직업 | 甲 곰🐻 숲지기 / 乙 사슴🦌 꽃집 주인 / 丙 사자🦁 무대 감독 / 丁 고양이🐱 등대지기 / 戊 코끼리🐘 산지기 / 己 너구리🦝 정원사 / 庚 늑대🐺 대장장이 / 辛 여우🦊 보석상 / 壬 고래🐳 항해사 / 癸 수달🦦 연구원 |
| 일지 → 소품 | 子 🌙달 / 丑 🍵찻잔 / 寅 🧭나침반 / 卯 🌸벚꽃 / 辰 ☁️구름 / 巳 🔮수정구 / 午 ☀️햇살 / 未 🧺바구니 / 申 🎒배낭 / 酉 🔔종 / 戌 🛡️방패 / 亥 🌊파도 |
| 우세 십성 → 수식어 | 비겁 뚝심 있는 / 식상 수다쟁이 / 재성 야무진 / 관성 듬직한 / 인성 생각 많은 |
| 신강/중화/신약 → 말투 칩 | 당당한 / 균형 잡힌 / 조심스러운 |
| 일간 오행 → 배경색 | 木 초록 / 火 빨강 / 土 황토 / 金 회색 / 水 하늘 (v1 `PillarsTable` 색과 동일 토큰) |

- 닉네임 = `{수식어} {직업} {동물}`. 샘플(1990/3/15, 己 일간, 관성 우세) → **"듬직한 정원사 너구리"**.
- 말풍선: 상황 3(연애할 때 / 일할 때 / 스트레스 받을 때) × 우세 십성 5 = 15문장. `bubbles`는 우세 십성에 맞는 3문장.
- 그림은 이모지로 시작한다. 캐릭터 그림은 `CharacterCard` 안의 이미지 슬롯 하나로 격리해서 이후 일러스트로 바꿔도 다른 코드는 바뀌지 않는다.
- 알려진 한계: 이모지는 OS마다 모양이 다르다. 공유 PNG에도 만드는 기기의 이모지가 찍힌다. 같은 모양이 필요해지면 일러스트로 교체한다.

## 4. 카드형 풀이 (`readings.json`, `interpret.ts`, `ReadingCard`)

```ts
type Section = { title: string; summary: string; chips: string[]; bullets: string[]; more: string[]; meter?: { label: string; value: number }[] }
```

- 기존 `body` 줄글은 `more`로 이동한다(내용 그대로 재사용).
- 새로 쓰는 문구: 항목마다 `summary` 1 + `chips` 3 + `bullets` 3. 대상 키: 일간 10, 일지 12, 십성 그룹 5(성향·직업 각각), 오행 부족 5, 신강/신약 3, 용신 5.
- `meter`: 오행 균형 카드는 오행 5개 막대(기존 `ElementChart` 재사용), 사주 구조 카드는 신강/신약 비율 막대.
- 섹션 제목과 순서(기본 성향, 사주 구조, 오행 균형, 직업·활동 경향, 조언)는 v1과 같다.
- `ReadingCard`는 요약(굵게) → 칩 → 불릿 → 막대(있을 때) → "더 보기" 접기 순서로 그린다. 접기는 새 라이브러리 없이 `<details>` 요소를 쓴다.
