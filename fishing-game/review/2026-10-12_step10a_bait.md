- 날짜: 2026-10-12
- 검수 담당 (읽기 전용, 수정 없음)
- 기준: GDD 6번 "미끼 효과 [확정]", 7번(없는 구분은 흔함으로 합침)
- 대상: `fish game/Assets/Scripts/Bait.cs`(WaitMin/WaitMax/Weights), `Fish.cs`(Pick(Period, Bait)), `FishingRod.cs`(Land 대기시간, Hook의 Pick, biteWaitMin/Max 삭제)

## 항목별 결과

| 항목 | 결과 | 내용 |
|---|---|---|
| (1) GDD 수치 일치 | 통과 | 지렁이 3~8초 70/25/5, 새우 5~10초 65/25/10, 빵 1.5~4초 72.5/25/2.5. 코드와 GDD가 전부 같음. 무한(소모 없음)도 코드에 개수 개념이 없어 맞음. |
| (2) 던질 때 고른 미끼 사용 | 통과 | `Cast()`에서 `castBait = selectedBait`로 고정. 대기시간(`Random.Range(WaitMin(castBait), WaitMax(castBait))`)과 물고기 선택(`Pick(TimeOfDay.Current, castBait)`) 둘 다 `castBait`만 읽음. `selectedBait`를 직접 읽는 곳은 라벨 표시뿐. 숫자키는 `state == Idle`일 때만 받으므로 던진 뒤 바꿔도 영향 없음. |
| (3) 흔함 합침 로직 | 통과 | `Weights()`가 호출마다 새 배열을 만들어서 Pick 안에서 `w`를 고쳐도 원본이 오염되지 않음. 보통/희귀 풀이 비면 그 확률을 w[0]에 더하고 0으로 만든 뒤 합계로 뽑으므로 새 가중치에서도 정확. 자동 시험 낮(보통 없음): 지렁이 95.1/0/5.0 (=70+25 / 5), 새우 90.2/0/9.8, 빵 97.5/0/2.5 모두 이론값과 일치. 밤 3구분도 69.9/25.3/4.9 등 오차 범위. |
| (4) biteWaitMin/Max 잔여 참조 | 통과 | .cs 전체 검색 결과 코드에는 남은 사용처 없음. 남은 건 `SampleScene.unity` 2911~2912줄의 직렬화 값(3, 8)뿐. 의견: 유니티는 클래스에 없는 직렬화 필드를 읽을 때 무시하고 다음 씬 저장 때 제거하므로 무해. 오류·경고 없고 동작 영향 없음. 굳이 손으로 지우지 않아도 됨. |
| (5) 요청 밖 변경 | 통과 | 스크립트 변경은 Bait.cs, Fish.cs, FishingRod.cs의 위 내용뿐(주석 정리 포함). 낚싯대 업그레이드·릴 감기·UI 변경 없음. GDD와 changelog도 함께 갱신됨. |
| 컴파일 | 통과 | 제출된 자동 시험상 오류 없음. |

## 참고 (반려 아님)

- 대기시간 자동 시험은 범위만 확인(3-8, 5-10, 1.5-4). 직접 플레이로 새우가 느리고 빵이 빠른지 체감 확인 필요.
- 낚았다 문구 끝에 "미끼: ..."가 `castBait` 기준으로 표시되어 일관됨.
- 낮 시간대 새우의 희귀 확률은 합침 때문에 약 10%라 "희귀 2배" 느낌이 낮에도 유지됨(보통이 없어 흔함에만 더해지므로 희귀 몫은 그대로).
