## 반려 사유: Esc로 도감을 닫으면 커서가 다시 풀림

실행 순서가 CatalogUI(-20) → FishingRod(-10) → PlayerController(0)예요.
같은 프레임에 Esc를 누르면:
1. CatalogUI가 먼저 도감을 닫고 커서를 고정하고 `IsOpen`을 false로 바꿔요.
2. 바로 뒤에 PlayerController가 돌 때는 이미 `IsOpen`이 false라서 return 되지 않고, 같은 Esc 입력(`wasPressedThisFrame`)을 보고 커서를 다시 **풀어 버려요**.

결과: Esc로 닫으면 커서가 풀린 채 게임으로 돌아와요. 합의한 "닫을 때 커서 다시 고정"과 어긋나요. (Tab으로 닫을 때는 문제 없음. 풀린 커서에서 한 번 클릭하면 다시 고정되긴 하지만, 그 클릭은 던지기에 안 쓰여서 클릭이 한 번 낭비돼요.)

## 고칠 곳 (수정은 구현 담당 몫)

- 같은 프레임의 Esc를 PlayerController가 못 보게 하기. 예: CatalogUI가 "이번 프레임에 닫혔음"을 알려 주고 PlayerController가 그 프레임은 Esc 처리를 건너뛰기.
- 고친 뒤 재검수 요청.

## 한계

- 플레이 모드는 실행하지 않았어요. Tab·Esc 입력 흐름은 실행 순서와 코드로 판단했어요.

## 재검수 (같은 날, 읽기 전용)

| 항목 | 결과 | 내용 |
|---|---|---|
| Esc로 닫기 | 통과 | CatalogUI.SetOpen(false)가 ClosedFrame = Time.frameCount 기록 → 같은 프레임에 PlayerController가 `Time.frameCount == ClosedFrame`이라 바로 return → Esc를 또 처리하지 않아 커서가 잠긴 채 유지. |
| Tab으로 닫기 | 통과 | 같은 경로(SetOpen(false))라 커서 잠김 유지. Tab은 PlayerController가 쓰는 키가 아님. |
| 열고 닫기 중 다른 동작 | 통과 | 열려 있는 동안은 기존대로 IsOpen으로 차단. 닫힌 프레임 하나만 시점·이동이 건너뛰어지는데 체감 없음. |
| 컴파일 | 통과 | 컴파일 중 아님, CatalogUI 타입과 ClosedFrame 확인됨. |
| 콘솔 | 통과 | 에러 0, 경고 0 (이전 SendMessage 시험 에러도 지워짐). |
| 이전 통과 항목 | 통과 | 수정은 CatalogUI 2줄·PlayerController 1줄뿐, 나머지 코드 그대로. |
