# 연차 · 반차 결재

직원이 연차/반차 결재를 올리고, 승인/반려하면 남은 연차가 자동으로 계산되는 작은 웹앱.
**한 페이지**에서 사원 현황, 신청, 승인 대기, 처리 내역, 사원 관리를 모두 한다. 별도 관리자 계정은 없다.

## 규칙

| 항목 | 규칙 |
| --- | --- |
| 기준 | 입사일 기준 |
| 입사 1년 미만 | 개근한 달마다 1개씩 발생 (최대 11개) |
| 입사 1년부터 | 입사 기념일마다 15개 발생 |
| 이월 | 없음 — 기념일이 지나면 안 쓴 연차는 소멸 |
| 차감 | 연차 1일 = 1, 반차(오전/오후) = 0.5. 주말은 제외 |
| 잔여 | 발생 − 승인된 사용 − 승인 대기 중인 신청 |
| 취소 | 취소/반려하면 즉시 복구. 대기 건과 아직 끝나지 않은 승인 건을 취소할 수 있음 |

공휴일은 따로 빼지 않는다(공휴일에 연차를 올리지 않는다고 가정).
신청 한 건은 하나의 연차 기간(입사 기념일 ~ 다음 기념일 전날) 안에 있어야 한다.

## 접근 방식 (신뢰 기반)

비밀번호 없이 **회사 공용 링크 하나**(`/?t=<긴 랜덤 토큰>`)로 접속한다.

- 링크를 아는 사람은 **누구나** 사원 목록과 잔여를 보고, 누구 이름으로든 신청하고, 승인/반려하고, 사원을 추가·수정할 수 있다.
  신청자 확인이나 승인 권한 구분은 없다.
- 테이블은 RLS 로 막혀 있어 anon 키로 직접 읽을 수 없고, 공용 토큰을 검증하는 DB 함수(RPC)로만 접근한다.
- 링크가 밖으로 나갔거나 퇴사자가 생기면 화면 아래 **사원 관리 → 공용 링크 재발급**으로 기존 링크를 즉시 무효화한다.
- 접속 후 토큰은 브라우저에 저장되고 주소창에서는 지워진다.

## 설치

1. Supabase SQL 편집기(또는 마이그레이션)로 `supabase/schema.sql` 을 실행한다.
   빈 DB에도, 이전 버전(관리자/개인 링크 방식)이 적용된 DB에도 그대로 실행할 수 있다(여러 번 실행해도 안전).
2. 공용 링크 토큰을 확인한다: `select value from app_settings where key = 'access_token';`
3. `.env.example` 을 `.env` 로 복사해 `VITE_SUPABASE_URL`, `VITE_SUPABASE_ANON_KEY` 를 채운다.
4. `npm install && npm run dev` → `http://localhost:5173/?t=<토큰>`
5. 화면 아래 **사원 관리**에서 사원을 추가하고, **공용 링크 복사**로 전달한다.

배포는 Vercel 에서 이 폴더(`leave_app`)를 Root Directory 로 지정하고 위 두 환경변수를 넣으면 된다.
(Vercel Authentication 은 꺼야 직원들이 로그인 없이 접속할 수 있다.)

## 테스트

```bash
npm test                                       # 화면 보조 로직
psql -v ON_ERROR_STOP=1 -f supabase/test.sql   # 발생/차감/승인/공용 링크 규칙 (schema.sql 적용된 DB에서, 끝나면 롤백)
```

`test.sql` 은 `anon`, `authenticated` 롤과 `extensions` 스키마(+pgcrypto)가 있는 DB를 가정한다(Supabase 기본값).
